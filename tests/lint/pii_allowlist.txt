# PII-check allowlist — the SINGLE source of truth for "this address identifies nobody".
#
# Consumed by BOTH:
#   - tests/lint/pii_check.py        (pre-commit + CI: blocks a real contact at commit time)
#   - scripts/oss-export.sh          (release gate: blocks a real contact reaching the public cut)
# Keeping one file avoids the drift footgun that has bitten the SHIPPING_DOCS /
# EXPECT_SKILLS_PUBLIC mirrors repeatedly — never copy these values into a second list.
#
# WHY THIS EXISTS. Prospecting features are written against real, messy data, so the
# tempting fixture is the row that actually broke the parser — a real person at a real
# company, pulled from a live RocketReach/Apollo run. That shipped to the public repo in
# v0.8.0 (see CHANGELOG 0.9.1). The de-brand token lint cannot catch it: the tenant's name
# is absent, so every gate passes. Hence a rule about OTHER people's identities.
#
# THE RULE. An email address in the shippable source surface must be provably non-real:
#   - an RFC-2606 reserved domain  (*.example, *.invalid, *.test, *.localhost, example.com)
#   - a single-letter placeholder  (a@x.com, b@y.com)
#   - a fictional domain declared below
#   - a full address declared below
# Anything else is treated as a real person until a human says otherwise.
#
# ADDING AN ENTRY. Prefer inventing a new .example domain over allowlisting a real one.
# Only add a real domain when it is a vendor/protocol shape with no person attached
# (an API host, a BCC ingest address), and say why on the comment line above it.
# NEVER add a free-mail domain wholesale — a real prospect's gmail is exactly what this
# gate exists to catch; pin the specific fixture address instead.
